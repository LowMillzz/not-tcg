# BYO AI recognition: documented paths and a testable contract

Checked: **2026-10-31 UTC**. Every external source linked below was checked on that date. This is documentation research for issue `03-byo-ai-recognition`, not an adapter selection or implementation approval.

## Verdict

**Proceed to bounded recognition experiments; five-second feasibility remains unproved.** OpenAI, Anthropic, Google, and local vision runtimes document ways to accept a crop and return structured data. Apple Vision supplies an on-device OCR path. These capabilities establish experiments worth running, not correct Pokémon identities, reliable slab-label reading, endpoint interchangeability, or auction-time performance. No inference, capture, credential inspection, account creation, or Mac validation was performed.

Keep both English raw singles and graded slabs in the experiment and launch requirements. If either fails the eventual correctness or timing bar, report a launch-scope conflict for a human decision. Recognition and sourced pricing are separate outcomes; model-generated prices are excluded.

**Material findings:** Gemini's current terms raise a consumer-use eligibility question for the collector scope. Provider retention differs from local screenshot disposal, with recent Google logging changes and apparently inconsistent Anthropic default-retention descriptions. A legacy catalog often used in examples is deprecated and closed to new registrations. These issues must remain visible rather than be hidden by an adapter abstraction.

**Compatibility is a feature matrix, not a base-URL substitution.** Google documents an OpenAI-compatible endpoint with image and structured-output examples, but recommends its native API for new integrations. Ollama explicitly supports only a subset of OpenAI's API and documents non-stateful Responses support. Neither fact supports universal equivalence of Responses, Chat Completions, tools, schema enforcement, usage accounting, or cancellation. [Google compatibility](https://ai.google.dev/gemini-api/docs/openai), [Ollama compatibility](https://docs.ollama.com/api/openai-compatibility)

**Proposal:** prefer a small number of explicitly tested protocol/model pairs. Allow an advanced compatible-endpoint configuration only after a conformance check. A generic “OpenAI-compatible” badge, `/models` response, or successful text completion must not enable recognition.

## Evidence: Apple's on-device OCR

Apple documents `VNRecognizeTextRequest` with fast and accurate paths, optional language correction, supported-language queries, custom vocabulary, candidate strings/confidence, and normalized text bounding boxes. Accurate recognition is the default. Apple says Vision processing occurs on the user's device. The official article's Markdown representation was successfully retrieved after its HTML required JavaScript. [Recognizing text in images](https://developer.apple.com/documentation/vision/recognizing-text-in-images), [retrieved Markdown](https://developer.apple.com/documentation/vision/recognizing-text-in-images.md)

**Proposal, unmeasured:** run OCR against the single hotkey crop, prioritizing name/collector-number areas for raw cards and label/card areas for slabs. Query a permitted local catalog index using the observed strings. Return without cloud inference only when the evidence distinguishes the complete required identity. Otherwise send the crop and clearly marked OCR observations to the configured vision model, or abstain. OCR is optional preprocessing, not a replacement for raw or slab coverage.

Benchmark `.fast` and `.accurate`, English configuration, and correction on/off. Custom card-name vocabulary may help names; language correction may also corrupt collector numbers, cert numbers, or uncommon text. These are hypotheses. Raising minimum text height could exclude precisely the tiny collector number required here; Apple's performance advice is not a reason to discard that evidence. [Apple's OCR performance discussion](https://developer.apple.com/videos/play/wwdc2019/234/)

A serial OCR-then-AI fallback adds OCR time to the slow path. Whether reduced cloud usage offsets that delay is unknown. Measure serial gating and any future concurrent alternative separately; do not silently incur a cloud call for a user selecting a local-only path.

## Identity verification and abstention proposal

The recognizer returns **observations and candidates**, not authoritative catalog IDs, grades, condition assessments, or prices. A bounded catalog candidate list supplied to the model could constrain selection, but retrieval correctness and extra latency remain unmeasured.

1. Preserve observed text separately from normalized guesses. Fields include language, card name, printed collector number (including prefixes/suffixes and denominator where visible), set text/symbol observation, printing/edition, finish/foil or stamp observations, and missing distinguishing evidence. Unknown stays null; similar artwork or name alone cannot identify a printing.
2. Resolve against a real catalog namespace and version outside the model. Verify that every proposed ID exists and its attributes agree with the visible evidence. A unique catalog hit is necessary but not sufficient if the catalog omits a relevant variant. Preserve unresolved finish/edition as ambiguity and block price matching that requires it.
3. For slabs, separately preserve grader label text, grade label as a string, qualifiers, designation/subgrades when relevant, and cert-number text as a string. Do not confuse grade with card number, assume every `10` means the same grader's grade, collapse designations, or infer grader from holder shape alone. Grader/grade normalization needs an approved allowlist and grader-specific rules.
4. Catalog identity, label transcription, cert-record verification, and physical authenticity are different states. PSA offers cert lookup and explicitly warns that real cert numbers can appear on counterfeit inserts. This is an example of verification semantics, not a selected launch grader or a verified automation API. No free automated cert-verification access was established in this research. [PSA cert verification](https://www.psacard.com/cert)
5. A crop of a raw card must not produce a slab grade or a reliable physical-condition grade. Leave raw condition unknown or explicitly user-supplied for subsequent pricing scenarios. A slab with an unreadable grade remains a slab with unknown grade; do not quietly route it as raw.
6. Zero or multiple plausible identities, occluded digits, lookalike variants, multiple cards, transitions, glare, and non-English or unsupported material produce an explicit ambiguous/out-of-scope result. No guessed comparable sale or fair price fills the gap. Model/OCR confidence is not a calibrated probability of a correct price match.

**Catalog dependency warning, narrowly checked for identity feasibility:** the Pokémon TCG API's own card-object documentation distinguishes an object ID from printed card attributes, and now announces deprecation, no new registrations, and existing-key operation only through March 1, 2027. Do not hardcode that namespace or assume a new user can obtain its key. Catalog selection and raw/slab price coverage remain outside this ticket. [Card object and service notice](https://docs.pokemontcg.io/api-reference/cards/card-object/)

## Credentials, transport deadlines, cancellation, and quotas

**Published authentication facts:** OpenAI uses bearer credentials with optional organization/project context. Anthropic's API overview requires an API key or configured federation; direct requests require an API-version header and may require workspace selection. Google requires a Gemini API key and is transitioning to authorization keys; new AI Studio keys default to that type since May 28, 2026. These are API credentials, not proof that a desktop chat subscription grants API usage. [OpenAI authentication](https://developers.openai.com/api/reference/overview#authentication), [Anthropic overview](https://platform.claude.com/docs/en/api/overview), [Google keys](https://ai.google.dev/gemini-api/docs/api-key)

Ollama's local compatibility examples ignore the client library's placeholder API-key value. LM Studio defaults to no API authentication and supports optional tokens. Do not send a real hosted-provider key to a local runtime just because its client constructor requires a value. [Ollama local compatibility](https://docs.ollama.com/api/openai-compatibility), [LM Studio authentication](https://lmstudio.ai/docs/developer/core/authentication)

**Published timeout/cancellation facts:** OpenAI's TypeScript SDK defaults to a ten-minute timeout and two retries; it accepts an `AbortSignal`. Anthropic's TypeScript SDK also defaults to two retries and a timeout of at least ten minutes, with longer calculated timeouts for large non-streaming outputs; it documents stream abort. Google exposes HTTP timeout/retry options; its retry-options reference defaults to five total attempts, and Generate Content's abort signal is explicitly client-only and does not stop service-side charges. These are examples of client behavior, not a recommended Swift dependency or a universal server-cancellation guarantee. [OpenAI SDK](https://developers.openai.com/api/reference/typescript), [Anthropic SDK](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/typescript), [Google HTTP options](https://googleapis.github.io/js-genai/release_docs/interfaces/types.HttpOptions.html), [Google retries](https://googleapis.github.io/js-genai/release_docs/interfaces/types.HttpRetryOptions.html), [Google abort semantics](https://googleapis.github.io/js-genai/release_docs/interfaces/types.GenerateContentConfig.html#abortSignal)

OpenAI documents request/token limits and response headers. Anthropic measures RPM, input TPM and output TPM; retry advice depends on the error, and spend caps differ from transient throttling. Google quotas apply per project rather than per key and can include RPM, TPM and daily limits; account/model tiers vary. No universal free-tier quota or five-second capacity is established. [OpenAI limits](https://developers.openai.com/api/docs/guides/rate-limits), [Anthropic limits](https://platform.claude.com/docs/en/api/rate-limits), [Google limits](https://ai.google.dev/gemini-api/docs/rate-limits)

**Proposal:** use an absolute deadline covering queueing, connection, upload, generation, parsing, validation, and any retry. Derive recognition's budget from the approximately five-second total after reserving time for catalog/pricing/UI work. Disable hidden SDK retries and automatic continuation for the initial experiment; Google's Generate Content SDK documents automatic continuation enabled by default. [Continuation setting](https://googleapis.github.io/js-genai/release_docs/interfaces/types.GenerateContentConfig.html#automaticContinuation) Stop local work/transport on cancel, timeout, or a superseding hotkey; reject late results by capture ID. Do not promise stopping billing or remote retention. Only retry if the remaining deadline and server delay permit it; never retry credential, billing, unsupported-schema, or invalid-model errors automatically. A local server's compute-stop behavior remains an unverified runtime-specific property.

## Retention and inference cost

These are **provider-published policies**, not an audit of a user's account. App disposal of pixels cannot establish provider deletion.

- **OpenAI:** API data is not used for training by default. The data-controls page lists default abuse-monitoring retention of up to 30 days and Responses application state of at least 30 days by default/when stored. Propose explicit `store: false`; it does not remove abuse monitoring. ZDR requires eligibility/configuration; image/file safety-review exceptions and caching still require disclosure. Avoid persistent Files/Conversations for a single crop. [Data controls](https://developers.openai.com/api/docs/guides/your-data)
- **Anthropic:** the current platform page says conversation content is not retained by default except Covered Models requiring 30 days; structured-output schemas may be cached for up to 24 hours. However, its linked commercial privacy article, dated July 1, says API inputs/outputs are deleted within 30 days, with policy/legal and other exceptions. **This is a documentation discrepancy or unresolved difference in arrangements; do not advertise universal zero retention.** Verify the selected model, features and account arrangement before publishing onboarding claims. [Platform retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention), [Commercial retention](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data), [Schema handling](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
- **Google:** unpaid-service terms allow product improvement and human review; paid-service terms say prompts/responses are not used for improvement, subject to stated exceptions and regional rules. Abuse monitoring separately documents 55-day retention of prompts, context and outputs. [Terms](https://ai.google.dev/gemini-api/terms), [Abuse monitoring](https://ai.google.dev/gemini-api/docs/usage-policies)
- **Google project logs:** logging defaults on for Interactions and for Generate Content in projects created on/after October 26, 2026. Logged requests/responses default to a maximum 55-day window before being marked for deletion; datasets can retain them longer. Generate Content's `store` config can override project logging. A no-store setting must be verified for the exact adapter and does not erase separate abuse monitoring. [Logging policy](https://ai.google.dev/gemini-api/docs/logs-policy), [Generate Content config](https://googleapis.github.io/js-genai/release_docs/interfaces/types.GenerateContentConfig.html#store)
- **Local/custom:** Ollama says it does not see prompts/data when running locally and documents disabling cloud features. This does not audit local logs, a remote proxy, or every compatible service. Require explicit local-model configuration before labeling a path on-device; custom endpoints need their own operator retention statement. [Ollama FAQ](https://docs.ollama.com/faq)

**Google scope question:** current terms state professional/business use, “not for consumer use,” restrict availability by region, and require paid services for API clients made available in the EEA, Switzerland or UK. The first user here is a collector. Record provider eligibility as unresolved pending human/provider clarification; do not silently reclassify the product or promise a Gemini launch adapter. This observation is not a legal determination. [Current additional terms](https://ai.google.dev/gemini-api/terms)

Inference may be user-paid even with entirely free price-data dependencies. Providers publish model-specific token prices, cached-input categories and other modifiers; Google advertises a limited free tier for some models. A free model quota is neither universal availability nor the launch pricing-data solution. [OpenAI pricing](https://developers.openai.com/api/docs/pricing), [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing), [Google pricing](https://ai.google.dev/gemini-api/docs/pricing)

**Proposal:** estimate each request from image-plus-text input, bounded output/thinking, cache writes/reads, and the selected service tier; label the result an estimate. Account for retries, abandoned calls, token-counting requests if billable, and provider-side continuation. Record returned usage when available; an aborted call with no usage response has unknown final cost. Local inference avoids hosted token billing but consumes RAM/compute and requires model downloads. Do not prewarm using paid calls without an explicit future test budget. Keep crops in memory only by default, show the capture/upload indicator, redact payloads and keys from logs, and store user keys in macOS Keychain on their owning host. These are proposals, not changes made here.

## Minimal compatibility-contract proposal

This is a decision input, not a production schema.

- **Configuration identity:** exact protocol, base URL/origin, API version, model ID/revision, runtime version/quantization for local use, required headers, user-owned credential reference, and retention/cost disclosure. Keep credentials separate from shareable config; require HTTPS for hosted origins and explicit loopback treatment for local servers. Changing destination must not automatically forward another provider's secret.
- **One bounded request:** one selected-region crop containing a raw single or slab, JPEG/PNG MIME and dimensions, capture ID/timestamp, absolute deadline, schema version and output cap. No full desktop, conversation history, external tools, or web search is required. Both card and slab label must fit the slab crop; missing pixels trigger abstention or a new user capture.
- **One normalized result:** outcome `candidates | ambiguous | unsupported | refused | timed_out | canceled | error`; zero to three candidate observations as an initial proposed bound; nullable identity/label fields described above; observed versus inferred evidence per field; warnings; actual model/request ID and usage if returned. Catalog resolution happens afterward with namespace/version and evidence status. No price field and no model-asserted `verified` flag.
- **Small common schema:** objects, arrays, strings, booleans, nullable fields and enums; required keys with null for unavailable values. Translate explicitly into each provider's supported subset, then validate the full application contract locally. Treat strict tool arguments as extraction data only, never permission to execute actions. JSON-only fallback is an explicit weaker capability requiring parsing/validation, not claimed strict compatibility.
- **Conformance gate:** future synthetic, nonprivate images with randomized visible text and image-absent controls; verify image input is actually used, null/ambiguous cases work, strict/JSON differences are reported, output limits and refusal/truncation are handled, and cancel/deadline/stale-result behavior works. Test image and schema together, then a separately labeled card/slab corpus. Endpoint discovery alone does not pass.
- **Failures:** user-readable auth/quota/model/transport/format/identity states; no successful identity implied by HTTP 200 or valid JSON. A superseded or overdue result cannot refresh the current price panel. No background retry queue extending beyond the bidding opportunity.

## Future measurements and unverified assumptions

**No measured latency or recognition accuracy exists from this work.** Marketing descriptions such as fast, accurate or multimodal are provider claims. No paid or free inference call was made.

Proposed experiment after separate authorization:

1. Build a permissioned labeled crop corpus spanning both raw and slabs: readable/obscured collector numbers, foil/edition lookalikes, old/new labels, grader/grade designations, motion blur, glare, rotation, hands, transitions, multiple cards and non-English negatives. Label what is actually visible, expected catalog candidates and required abstentions. Keep development/tuning images separate from held-out evaluation.
2. Compare OCR/catalog alone, direct vision, and OCR/catalog with AI fallback. Vary crop pixel dimensions, encoded size/compression and provider detail/media-resolution settings. Keep original text legibility in the record: upscaling blur is not new evidence. Do not infer performance on unsupported graders or omit hard slab cases from the denominator.
3. Measure hotkey-to-validated identity and hotkey-to-sourced guidance separately, plus crop/preprocess/OCR, catalog, connection/upload, first byte/token, complete valid output, verification and UI stages. Report p50/p95/tail, timeouts, costs and usable-result coverage; first token is not a usable identity. Price-data latency is a separate downstream budget, not measured here.
4. Separate first request/new schema, warm schema, local model unloaded versus resident, and actual cache-hit/miss conditions. Ollama exposes model load duration, evaluation durations and cached prompt counts; use these as diagnostics, not substitutes for end-to-end timing. [Chat API metrics](https://docs.ollama.com/api/chat)
5. Record Mac chip/RAM/OS, concurrent video playback and resource pressure, runtime/model versions, network geography/RTT and observed provider routing. Repeat across networks/times. Network distance, queueing and cold state are plausible latency drivers, not quantified results here.
6. Measure exact printing accuracy and slab grader/grade/qualifier transcription, candidate recall, false confident matches, abstention coverage and performance conditional on readable evidence. Separate accurate extraction from catalog coverage. Do not hide timeout/errors by reporting accuracy only on completed calls.
7. Inject canceled/superseded requests, deadline expiry, 401/403, quota/spend and rate-limit errors, malformed/truncated/semantically wrong JSON and catalog conflicts in a later test harness. Compare retry-disabled operation with any subsequently approved bounded retry; report extra latency and spend. Cache hits for repeated images must not reuse a grade or variant without validating the capture identity.

Unverified: any named model's Pokémon expertise; usable accuracy from auction crops; catalog completeness for printing/finish; graders/grades supported at launch; ordinary new-account access and effective quotas; local memory fit and thermal behavior; server-side cancellation effects; custom endpoint retention; human acceptance of abstention; and the recognition share of the total deadline. Documentation cannot settle these.
